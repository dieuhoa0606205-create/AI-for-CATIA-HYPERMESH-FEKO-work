# Surface-first element grouping for HyperMesh → FEKO

[中文](README.zh-CN.md)

A grouping pattern for FEKO boundary groups. It decides group membership on
CAD surfaces before the production mesh, then moves elements by surface: one
mark and one move per group. The number of grouping operations scales with the
number of groups, not with the number of elements; each mark and move still
processes the associated elements internally.

This note describes the grouping step only. It is not a complete CATIA → FEKO
pipeline, a meshing algorithm, or a CAD cleanup recipe.

## When it applies

- The mesh is generated by HyperMesh from CAD surfaces.
- Every boundary group is a union of whole surfaces.
- A group is defined by the media on the two sides of a surface, plus any
  face-only attribute such as a perfect-conductor sheet, an impedance boundary
  or a symmetry plane.
- The surface-to-group mapping is known before the production mesh.

If a group must contain part of a surface, this pattern cannot express it.
Split the surface in CAD, or assign those elements individually. FEKO labels
are per triangle, so splitting a surface after meshing makes the geometry and
the labels disagree.

## Why not group elements one by one

After meshing, an element has an ID but no engineering identity. Its position
and neighbours do not say which boundary group it belongs to. A per-element
pass over a large mesh is slow, difficult to review, and sensitive to element
size, element order and local mesh density.

A surface does have that identity. There are tens of surfaces, not hundreds of
thousands of elements. The group decision can be written down, checked and
reused before any production element exists.

## The two records

Surface-first grouping composes two records:

| Record | Created by | Reviewed by |
|---|---|---|
| surface → group | the grouping table, before meshing | a person, surface by surface |
| element → surface | HyperMesh, when the surface is meshed | a coverage check, after meshing |

Together they give element → group. Neither record alone is enough.

The first record makes the method fast and reviewable. The second must be
verified, because it is created inside HyperMesh and does not appear in the
grouping table.

## Building the surface → group table

For each surface, record:

- the medium on the negative-normal side;
- the medium on the positive-normal side;
- any face-only tags.

The ordered pair matters: `air-carrier` and `carrier-air` are different
boundary groups. A face tag is appended to the group name, for example
`air-PEC` or `air-air-PEC`.

A surface with the same medium on both sides is not a boundary unless it
carries a face tag. A perfect-conductor sheet inside air is a real boundary:
both sides are air, but the face itself carries the conductor condition, so it
belongs in the table.

Group names should be stable and readable. They become the FEKO labels, so
preserve the orientation of the pair in the name.

If the media are not known, classify them on a reference mesh first. A common
method treats each material as a closed shell and tests which medium lies on
each side of the surface; that method requires every material to be a closed
shell in the reference mesh. The reference mesh must therefore contain every
surface that carries the material, including duplicates and surfaces that will
be removed later. Removing surfaces before classification opens the shells and
silently corrupts the pairs.

## Making the element → surface link explicit

There are two ways to know which elements came from which surface.

### Per-surface meshing

Mesh one surface at a time into a component named for that surface. Component
membership is then the record: an element in the component belongs to that
surface. This is useful for a reference mesh, where each surface needs its own
label for material classification.

### One-pass meshing

Mesh all surfaces in one call. Adjacent surfaces share edges, and a single
pass is used to keep the mesh conformal across those edges. Meshing each
surface separately can leave duplicate nodes at a boundary between groups.

The trade-off is that the element-to-surface link is no longer stored in a
component. It exists only as the association HyperMesh creates while meshing.

For the production mesh, prefer one pass and verify the association. For a
reference mesh used only for classification, per-surface components are the
point.

## Moving a group

HyperMesh can mark elements by the surface they are associated with:

```tcl
*createmark elems 1 "by surface" 12 13 14
*movemark elems 1 "group_name"
```

The first command marks every element associated with surfaces 12, 13 and 14.
The second moves the marked elements into the existing component named
`group_name`. No per-element loop is involved. A group with three surfaces
costs the same number of commands as a group with one surface; the element
count only affects how long the mark and move take internally.

A minimal procedure is in [`group_by_surface.tcl`](group_by_surface.tcl).

## Verifying the association

Before accepting the grouped mesh, check three things:

1. Every surface in the table has at least one associated element.
2. The per-surface counts sum to the union count. If the sum is larger, at
   least one element is claimed by two surfaces, so its group ownership is
   ambiguous; if the two surfaces belong to different groups, moving one group
   removes the element from the other.
3. When the surface list is meant to cover the whole mesh, the union count
   equals the total element count. Otherwise, elements that belong to no
   surface are outside every group.

[`check_surface_association.tcl`](check_surface_association.tcl) implements the
first two checks and returns the union count. Compare it with the mesh total
for the third.

Run the check before moving elements. After a move, the association may still
exist, but component membership no longer tells you which elements were
originally claimed by which surface.

If a check fails, stop. Do not export a grouped mesh whose association is
incomplete or ambiguous.

## Limitations

- The association is created at mesh time. Elements created manually, imported
  from another mesh, or copied from elsewhere may have no surface association.
- Geometry edits after meshing can invalidate the association. Re-mesh and
  re-group if the geometry changes.
- A surface belongs to exactly one group. The pattern cannot split one surface
  between two groups.
- The pattern validates grouping, not physics. The media pairs and face tags
  still need engineering review.
- The method assumes the mesh is generated from the listed surfaces. Elements
  outside that list are outside the grouping.
- A successful check says the association is complete and unambiguous. It does
  not say the mesh quality, the boundary conditions or the FEKO model are
  correct.

## Scope

This note stops at a grouped mesh. Importing that mesh into CADFEKO and
assigning boundary conditions are separate steps. The pattern is useful when
boundary groups follow CAD surfaces; it is not a general solution for labels
that vary inside a single surface.
